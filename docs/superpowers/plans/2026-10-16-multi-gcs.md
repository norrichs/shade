# Multiple Globule Cross Sections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A globule carries an ordered list of cross sections (GCSs) placed at silhouette levels; levels between them are linearly blended vertex-by-vertex.

**Architecture:** `GlobuleConfig.shapeConfig` becomes `shapeConfigs: ShapeConfig[]`. Pure modules in `src/lib/gcs/` compute effective levels, validate, and blend. The level pipeline takes a `PrototypeAt = (t) => LevelPrototype` function instead of a prototype/array. The main thread pre-validates and turns off (then back-fills from the last result) only the pipelines that consume an invalid globule.

**Tech Stack:** TypeScript, SvelteKit (Svelte 5 runes), Three.js, Jest.

**Spec:** `docs/superpowers/specs/2026-10-16-multi-gcs-design.md`

## Global Constraints

- One GCS ⇒ generated geometry byte-identical to today (proved by Task 1's snapshots).
- Band count, facets per band and band order never change between levels; only vertex positions.
- List order = silhouette-curve order: list[0] anchors nearest level 0 (start of the silhouette curve, physically the *top* on the default silhouette). No z-direction detection.
- Level indices are integers `0..divisions` where `divisions = levelConfig.silhouetteSampleMethod.divisions`; level `i` anchors at `t = i / divisions`.
- Blend is linear (`blend.mode: 'linear'`), evaluated on normalized 2D prototypes (output of `generateLevelPrototype`), before silhouette scale/offset/depth.
- Invalid GCS list blocks only pipelines consuming that globule; their previous output stays. GCS error toast fires only when the message changes.
- Never block the UI thread with geometry generation; validation (prototype sampling only) is allowed on the main thread.
- Run commands from the worktree root. Unit tests: `npm run test:unit -- <path>`.

## Review Focus

- Reducing silhouette divisions below a pinned level → validation error naming the GCS, not a crash or silent clamp (Task 3 test `pinned level out of range`).
- Changing the primary's sampling so others no longer match → error message names both vertex counts (Task 3 test `vertex count mismatch`).
- Deleting the primary GCS → first remaining becomes primary; config stays valid (Task 6 test `deleteGcs reassigns primary`).
- A pipeline the user turned off in View while the GCS is invalid must stay empty, not be back-filled with stale output (Task 5 test `user-disabled pipeline is not back-filled`).
- Legacy saved config / legacy projection surface `GlobuleConfig` with `shapeConfig` loads and renders as before (Task 2 tests `parseSavedConfig migrates` and `migrates projection surface`).

### Task 3: Placement and validation (pure)

**Files:**
- Create: `src/lib/gcs/gcs-placement.ts`, `src/lib/gcs/validate-shape-configs.ts`
- Test: `src/lib/gcs/__tests__/gcs-placement.test.ts`, `src/lib/gcs/__tests__/validate-shape-configs.test.ts`

**Interfaces:**
- Produces:
  - `effectiveGcsLevels(shapeConfigs: Pick<ShapeConfig,'level'>[], divisions: number): number[]` — no validation, just the rule below.
  - `gcsLabel(index: number): string` — `'A'`, `'B'`, …
  - `type GcsError = { index: number | null; message: string }` (`null` = list-level)
  - `type GcsValidation = { isValid: boolean; errors: GcsError[]; levels: number[]; bandCount: number }`
  - `validateShapeConfigs(shapeConfigs: ShapeConfig[], vertexCounts: number[], divisions: number): GcsValidation` — pure; caller supplies each GCS's prototype vertex count (keeps this module free of `generate-shape` imports, avoiding a cycle).

Placement rule (the tests pin it):
```
n === 1                       → [0]  (level ignored)
p[i] = shapeConfigs[i].level  (undefined = unpinned)
if p[0] undefined   → p[0] = 0
if p[n-1] undefined → p[n-1] = divisions
each run of unpinned between known p[a], p[b]:
  p[a+k] = Math.round(p[a] + (p[b] - p[a]) * k / (b - a))
```

Validation errors (exact copy; `X` = `gcsLabel(index)`):
- primary count ≠ 1 → `{ index: null, message: 'Exactly one cross section must be primary' }`
- `n > divisions + 1` → `{ index: null, message: 'More cross sections (n) than silhouette levels (divisions+1)' }` with numbers filled in
- pinned level not an integer or outside `0..divisions` → `{ index, message: 'X: level L is outside 0–D' }`
- vertex count ≠ primary's → `{ index, message: 'X has V points; primary has N' }`
- zero vertices → `{ index, message: 'X has no points' }`
- effective level ≤ previous effective level → `{ index, message: 'X: level L must be above previous cross section (level P)' }`
- With n === 1, only the zero-vertex check applies (level ignored, primary implied).
