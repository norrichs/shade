# Fix plan: overlapping bands in Voronoi surface-projection tubes

## Status

**Root cause CONFIRMED** — static analysis + empirical dev-server reproduction.

Empirical signature (band-striped 3D view of one surfaceProjection tube):

| surfaceProjectionDivisions | divA length | `reverse()` effect | result |
|----|----|----|----|
| 0 | 0 | no-op | clean (baseline) |
| 1 | 1 | no-op (single element) | clean |
| 2 | 2 | swaps the two | **broken — overlap/z-fight on the cA-side (upper) bands** |

`Array.reverse()` is identity for length ≤ 1 and only reorders at length ≥ 2. The bug threshold is
therefore *exactly* `divisions ≥ 2`, which uniquely matches `divA.reverse()` and rules out other
causes (a general ordering/offset bug would break at divisions 1 or 0 too). The cA-side (`divA`) bands
mottle while the cB-side (`divB`, un-reversed) stays clean — consistent with the asymmetric reverse.

## Symptom

Surface-projection tube bands overlap on one side when `surfaceProjectionDivisions > 0`.

## Root cause

In the per-edge `spSections` construction in `makeVoronoi`
([src/lib/voronoi/generate-voronoi.ts:431-461](../../src/lib/voronoi/generate-voronoi.ts#L431-L461)):

- `divA` is generated by `slerp(cA_dir, edge_dir, t)` for `t = 1/(n+1) … n/(n+1)`
  → pushed in order **nearest-cA → nearest-edge**.
- `divB` is generated by `slerp(edge_dir, cB_dir, t)`
  → pushed in order **nearest-edge → nearest-cB**, and is **not** reversed.
- The assembled profile is `[cA, ...divA.reverse(), edge, ...divB, cB]` (line 459).
  Reversing only `divA` makes the A-half run `cA, (near-edge) … (near-cA), edge` — **non-monotonic**.

Band construction (`generateProjectionBands`, `axial-right` branch,
[src/lib/projection-geometry/generate-projection.ts:714-732](../../src/lib/projection-geometry/generate-projection.ts#L714-L732))
makes band `f` the strip between `points[f]` and `points[f+1]`. A non-monotonic profile therefore
yields bands whose angular spans overlap (band 0 = wide `cA→near-edge` arc; bands 1..n nest inside it).
The B-half is correctly ordered, so overlap appears on the A-side only.

Latent because `surfaceProjectionDivisions` defaults to `0` ([:430](../../src/lib/voronoi/generate-voronoi.ts#L430)),
making `divA` empty and `reverse()` a no-op — the bug is invisible at default config.

## Fix (minimal, single change)

Drop the `.reverse()` so both halves are built consistently outward from `cA → edge → cB`:

```ts
// line 459
points: [cA.clone(), ...divA, edgePoint.clone(), ...divB, cB.clone()]
```

`divA` is already ordered nearest-cA → nearest-edge by the slerp, so no reversal is needed — this
mirrors how `divB` is (correctly) used un-reversed.

Alternative (equivalent, larger diff, not preferred): keep the reverse but build `divA` as
`slerp(edge_dir, cA_dir, t)`. Rejected — one-token removal is clearer and matches the B-side.

   and is absent at `0`. If overlap also occurs at `0`, STOP — there is a second root cause; do not

   - `const config = { ...makeTestConfig(), surfaceProjectionDivisions: 3 }`.
   - Call `makeVoronoi(config, { globule: 0 }, testSurfaceConfig)`.
   - For each `surfaceProjectionTube`, take a section's `points` and assert **angular monotonicity**
     about the projection center `C = getSurfaceCenter(testSurfaceConfig)`:
     - `u_k = (points[k] - C).normalize()`
     - axis `N = u_0 × u_last`; signed angle `θ_k = atan2((u_0 × u_k)·N̂, u_0·u_k)`
     - assert `θ_k` is non-decreasing across `k`.
   - This inspects `sections` (built before `generateProjectionBands`), so the existing
     band/`generateProjectionBands` mock does not interfere.
   - Verify the test is RED on current code (fails on the A-half), then proceed.

3. **Apply the one-line fix.** Remove `.reverse()`.

4. **Verify GREEN + no regressions.**
   - `npm run test:unit -- src/lib/voronoi/__tests__/generate-voronoi.test.ts`
   - `npm run check`
   - Dev-server visual confirmation with the user's repro config (overlap gone, both halves clean).

## Guard against an incomplete fix

- Assert monotonicity on **both** halves in the test, not just A — proves divB has no symmetric bug.
- The winding flip `spReversed` ([:472-475](../../src/lib/voronoi/generate-voronoi.ts#L472-L475)) reverses
  every section's points uniformly, preserving relative order — it does not affect monotonicity.
- Non-goal: the 3D `tubes` path (`combineSections`) has its own reversals and is out of scope here.

## Outcome (implemented — beads shades-c4v)

- Removed `.reverse()` on `divA` (and corrected the stale `divA_reversed` comment at :428).
- **Test metric changed during implementation.** The first attempt asserted angular monotonicity of
  the section profile about the projection center. That metric assumes the `cA→edge→cB` profile is
  planar; on a sphere it is a *bent* arc, so it flagged a benign ~95° kink at the edge centerline as
  a sub-degree "violation" even after the fix. Replaced with a **planarity-independent fold-back
  test**: the dot of consecutive profile-segment directions must stay `> -0.5` (no turn sharper than
  120°). Evidence for the threshold:
  - With bug (reverse present): `minFoldDot = -1.0` (full 180° fold-back → overlap).
  - With fix: worst kink `minFoldDot = -0.0839` (~95°, the legitimate edge bend, present at
    divisions 1 too — which the user confirmed looks correct).
  - Threshold `-0.5` sits with ~0.5 margin on both sides.
- Verified: new test RED with bug / GREEN with fix; full voronoi suite 6/6 green; `npm run check`
  introduces no new errors in the touched source (only pre-existing jest-globals noise in the test).
- **Still owed: visual confirmation in dev server at divisions ≥ 2** (mottling gone).
